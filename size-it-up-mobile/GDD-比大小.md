# 《比大小》（Scale Sense）游戏设计文档 GDD

> **版本**：v1.0 ｜ **日期**：2026-10-20 ｜ **对应原型**：`size-it-up-mobile/index.html`（已实现）
> **一句话定位**：一款测试「尺度感与数量级直觉」的移动端每日估测游戏合集——不考知识，只考直觉、拆解和敢猜。

## 1. 游戏概述

| 字段 | 内容 |
|---|---|
| 游戏名 | 比大小（Scale Sense） |
| 类型 | 休闲 / 益智 / 每日挑战（Daily Puzzle） |
| 平台 | 移动端 H5 优先（单文件、零依赖、免安装），可打包小程序 |
| 对标 | Magnitudle（Size It Up / Daily Question / Survival）、Wordle 的每日传播模型 |
| 目标用户 | 好奇心驱动的大众玩家；通勤碎片时间；喜欢 Wordle 类轻量挑战的用户 |
| 核心体验 | 「原来它是这么大/这么多！」的认知惊喜感（reveal 时刻） |
| 会话时长 | 视觉模式 2~3 分钟 / 每日一题 <1 分钟 / 生存模式 3~5 分钟 |

### 1.1 设计支柱（Design Pillars）

1. **零门槛，深直觉**：不需要任何专业知识，答对靠的是拆解与常识，而非记忆。
2. **揭晓即奖励**：每一轮的核心爽点是 lock-in 后的动画揭示——真实大小/真实数字带来的认知冲击。
3. **一日一会**：每日一题全站同题 + 连胜（streak）+ 一键分享战绩，复刻 Wordle 的社交裂变循环。

## 2. 玩法系统（五大模式）

### 2.1 模式总览

| 模式 | 类型 | 轮数 | 核心动作 | 状态 |
|---|---|---|---|---|
| 📏 比大小 · 日常 | 视觉 | 5 | 缩放目标物对比例 | 已实现 |
| 🎬 比大小 · 奇幻 | 视觉 | 5 | 同上，题库为知名角色 | 已实现 |
| 🌍 比大小 · 地理 | 视觉 | 5 | 同上，题库为地理尺度 | 已实现 |
| 🔢 数量级 · 每日一题 | 数值 | 1 | 费米估测，一次机会 | 已实现 |
| 💀 数量级 · 生存模式 | 数值 | 无限 | 限时限时扣血答到死 | 已实现 |

### 2.2 视觉模式（Size It Up 类）

**规则流：**
1. 每轮给出 **参考物**（蓝色，标注真实尺寸，如 成年人 1.7 米）+ **目标物**（红色，不标注）
2. 玩家拖动**对数滑块**缩放目标物，直到比例看起来符合真实世界
3. 点击「锁定答案」→ 目标物动画变绿并弹至真实比例（auto-fit 等比缩放舞台）
4. 结算面板：显示目标物真名 + 真实尺寸 + 玩家比例 + 偏差百分比 + 得分
5. 5 轮结束进入总结页：总分 /500、🟩🟨🟧🟥 战绩方块、逐题回放、一键复制分享

**关键机制：**
- **每题自适应量程**：滑块范围 = 真实比值 ±100 倍（全局钳制 [0.02, 100000]），保证从「网球 vs 苹果」到「楼房 vs 珠峰」都有足够精度
- **舞台 auto-fit**：比例极端时（楼房 vs 珠峰 = 2950 倍），双物体等比缩放以保住「相对关系」这一核心信息
- **随机起点**：每轮滑块初始位置随机（380~620），防止玩家形成肌肉记忆惯性
- **量程即信息**：不向玩家暴露当前倍数（否则数学好的人可以直接反推）

### 2.3 数量级 · 每日一题（Magnitudle Daily 类）

**规则流：**
1. 每天本地时间 0 点刷新，**全站同题**（按日期 `YYYYMMDD % 题库长度` 固定种子）
2. 玩家输入一个数字（可用快捷倍数键 ×1千 / ×1万 / ×1亿 / ×1万亿 / 清零）
3. **一次机会**，锁定后不可修改
4. 揭晓：你的估测 vs 正确答案（中文大数格式化，如「8 亿亿」）+ 相差几个数量级 + 冷知识注释
5. 计入连胜（streak），当日完成后主页显示「今日 N 分」，次日刷新

**设计意图**：考的不是记数字，是**费米估算**——把「全球一天心跳数」拆成「80 亿人 × 10 万次/天」。题目下方常驻提示文案引导这种思维方式。

### 2.4 数量级 · 生存模式（Survival）

| 参数 | 数值 |
|---|---|
| 初始生命 | 10 点 |
| 每题限时 | 15 秒（进度条由绿→橙→红） |
| 扣血规则 | max(1, round(数量级偏差))；超时直接 -3 |
| 回血规则 | 偏差 ≤ log10 阈值（答得极准）+1 生命，封顶 10 |
| 结束条件 | 生命 ≤ 0 |
| 结算 | 答对题数 + 累计分数，存历史最佳 |

**定位**：硬核玩家的技术验证场，也是唯一「无尽」模式，制造「再来一把」的冲动。原站为每周三开启、一次机会；本作先做成常驻练习模式，后续可加周赛锁。

## 3. 数值设计

### 3.1 计分公式

**视觉模式**（对数误差，对大小跨度公平）：

```
err = |ln(猜的比值 / 真实比值)|
err ≤ 0.06        → 100 分（约 ±6%）
否则              → max(0, 100 × (1 − (err − 0.06) / 1.54))
err ≥ 1.60        → 0 分（约差 5 倍）
```

**数值模式**（数量级距离）：

```
d = |log10(估测 / 真实值)|
d ≤ 0.06          → 100 分（约 ±15%）
否则              → max(0, 100 × (1 − (d − 0.06) / 4.94))
d ≥ 5             → 0 分（差 5 个数量级）
```

**设计原则**：差一个零 ≠ 灾难，差五个零才是。鼓励「正确的数量级」而非「精确的数字」，这正是费米估测的本质。

### 3.2 战绩方块映射（分享用）

| 单题得分 | 方块 |
|---|---|
| ≥ 90 | 🟩 |
| 60~89 | 🟨 |
| 30~59 | 🟧 |
| < 30 | 🟥 |

### 3.3 难度曲线

- 视觉模式题库隐含分档：日常物品（±10 倍内）→ 巨兽/建筑（10~300 倍）→ 地理奇观（300 倍以上），随机抽 5 天然形成节奏波动
- 数值题库覆盖 10²（圆珠笔 2 千米）到 10²⁴（地球质量），一天一题保证宽度
- 后续迭代：按历史得分动态偏移滑块初始位置、引入「干扰选项」式陷阱题

## 4. 内容系统

### 4.1 题库结构

```
视觉题：{ ref: {e:emoji, n:名称, s:米}, tgt: {e, n, s} }   // 参考物 / 目标物
数值题：{ q: 问题文本, a: 标准答案, u: 单位, note: 冷知识 }
```

- 当前题量：日常 16 / 奇幻 10 / 地理 10 / 数值 20
- **扩容目标**：每类 ≥ 50，随机抽题重复感才可接受
- 数值题需标注「约」值与信源年份，争议数据（如蚂蚁总数 2×10¹⁶）在 note 中说明量级而非精确值

### 4.2 每日刷新与防剧透

- 每日一题种子 = 本地日期，天然防剧透（提前看代码 = 提前知道题，仅自嗨）
- 完成状态按日期落盘（`bsz_daily_YYYYMMDD`），跨时区按本地 0 点
- 未来加「结果延迟显示」：答题期间不显示任何对错提示，全服统一时刻开榜（社交版本再做）

### 4.3 内容风险

- 奇幻模式角色名仅作标识性使用，尺寸为公开资料近似值，注明「约」，规避 IP 精度争议
- 地理/科学数据选权威来源，note 中保留一句可验证的解释

## 5. UI / UX（移动端优先）

| 设计点 | 决策 | 理由 |
|---|---|---|
| 布局 | 竖屏单列，max-width 480px 居中 | 手机单手 + 桌面预览双兼容 |
| 滑块 | 34px 大拇指键、对数映射 | 触控精度与跨数量级覆盖 |
| 缩放禁用 | `user-scalable=no` + `touch-action: manipulation` | 防双击缩放打断操作 |
| 计分反馈 | 揭晓面板 verdict 文案分 5 档（🎯🔥😊😅💥） | 情绪化反馈强化 replay |
| 进度 | 5 圆点实时染色（绿/黄/红） | 一眼看清本局走向 |
| 结算 | 大数字 + 方块 + 逐题回放 + 复制战绩 | 分享图的前身 |
| 导航 | 模式卡片即主页，左下统一「返回主页」 | 零层级迷路 |

**视觉风格**：浅色系、圆角卡片、单强调色模式化（蓝=视觉、紫=数值、橙=生存），信息密度高但不堆砌。

## 5.5 手感与引导（Game Feel，v1.1）

| 机制 | 实现 | 设计意图 |
|---|---|---|
| 合成音效 | Web Audio 振荡器现场合成（锁定咔哒 / 揭晓分档音 / 满分琶音 / 结束号角 / 生存倒计时滴答），零音频资源 | 零包体热更新友好；header 提供 🔊/🔇 开关（落盘） |
| 触屏震动 | `navigator.vibrate` 分档：锁定 10ms、错误 [30,30,30]、满分 [15,40,15] | 移动端独有的「物理确认感」 |
| 彩带庆祝 | Canvas 粒子（单题 100 分 / 总分 ≥90% / 生存 10 题） | 强化峰值时刻（peak-end rule） |
| 分数滚动 | rAF 三次缓出从 0 滚到得分 | 数字本身成为奖励动画 |
| emoji 单色染色 | CSS filter：猜测态单色红、揭晓态单色绿 | 对齐原版「红目标/蓝参考」剪影语言，修正 color 属性对彩色字形无效的问题 |
| 对数刻度尺 | 滑块下方按当前量程动态渲染 ×0.1/×1/×10/×100… 刻度 | 给玩家心算锚点但保留挑战（不显示当前精确倍数） |
| 草稿板 | 数值模式可折叠 textarea，内容持久化 | 费米拆解是玩法本身，给足工具 |
| 首启引导 | 每模式首次进入 6 秒自动消失的提示条（按 seen 标记只出一次） | 不打断、可跳过的软引导 |
| 极端比例提示 | 比值超 ±30 倍时提示「视图已缩放，比例关系真实」 | 防止「楼房 vs 珠峰」场景下的认知困惑 |
| 留存钩子可见化 | 主页 🔥连胜火焰、每日结算页距次日 0 点实时倒计时 | 把 streak 从数据变成情绪 |

## 6. 系统与留存

- **连胜（Streak）**：每日一题连续天数，断签归零——核心日活钩子
- **最佳纪录**：按模式分别落盘（`bsz_<mode>`），主页卡片直接展示，制造「破纪录」动机
- **分享循环**：战绩文本 = 模式名 + 方块行 + 总分 + 召唤语，剪贴板一键复制（后续接微信分享卡片/截图生成）
- **纪念性时刻**：满分 100 的 verdict 单独强化（🎯 完美！），满分局可触发彩蛋（待做）

## 7. 技术方案

- **形态**：单 HTML 文件，零依赖，任何静态托管可直接上线；微信小程序可用 webview 或重写移植
- **持久化**：`store` 安全封装——localStorage 可用时持久化，沙箱/隐私模式下自动降级内存存储（已踩坑修复）
- **热更新（v1.0.1 已实现）**：内容与代码分离，代码永不需要重发
  - 远程数据包 `data/pools.json`（含 `version` + 四类题库 + `daily` 按日期覆盖表）
  - 三级加载策略：**远程拉包（2.5s 超时、禁缓存）→ 本地缓存（上次成功包）→ 代码内置兜底题库**
  - 运营流程：改 `pools.json` 内容 → 递增 `version` → 重新上传，玩家下次打开自动生效
  - 每日一题运营位：`daily` 字段按 `YYYY-MM-DD` 推指定题目，不配置则按日期种子自动轮换
  - 主页底部显示内容包状态（已同步 / 离线缓存 / 内置），便于排查
  - 跨域要求：数据包与页面同域，或托管端开启 CORS
- **核心引擎复用**：视觉模式 3 套题库共享一个引擎（量程自适应 + auto-fit 渲染）；数值模式每日/生存共享一个输入引擎；热更新包通过原位替换题库数组生效，无需刷新页面
- **性能**：纯 DOM + CSS transition，无 canvas，低端机无压力
- **可扩展点**：对战模式接 WebSocket、周赛需要轻后端
